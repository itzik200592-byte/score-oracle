# Squad verification protocol (shared by score-sniper and situation-analyst)

The web is full of LAST SEASON'S previews: players who left, old managers, stale injury lists, pages with persistent URLs that are re-used every season. A player who left a year ago must never appear in our output. Follow this for every match, no exceptions:

1. **Pull the current squads first.** `cd C:\Users\itzik\Desktop\CLAUDE\score-oracle && PYTHONIOENCODING=utf-8 python -m oracle squad "<Home>" "<Away>"` (names exactly as in docs/data.json). This is ESPN's current roster with age, position and shirt number, refreshed daily. For Israeli domestic clubs ESPN has no rosters (Hapoel Be'er Sheva in Europe is the exception). For those, open the club's Sofascore page in the built-in browser (search the club on https://www.sofascore.com, team page, the paragraph "Current <club> players" near the bottom lists the squad by position; the coach is shown at the top), then store it with `python -m oracle squad-save "<Team>" --source "sofascore.com/<team url>" --players "Name, Name, ..."` so `oracle squad` and the verifier can use it for 30 days. Sofascore blocks scripts (HTTP 403); only read it through the browser, never through code, and never try to get around the block. If you cannot get a squad, say "סגל לא זמין לאימות" and make NO player-based adjustment for that team.
2. **Only players in the current roster may be named.** If an article mentions a player who is not in the roster, the article is stale or wrong: drop the whole claim and lower your trust in that source for this match. Managers: cross-check with a second, dated source before naming one.
3. **Dates.** Use only articles you can date to the last 7 days (a preview for THIS fixture with this season's date, a press conference, an official club post). If a page shows no date or last season's opponents/scores, treat it as stale. Note the date next to each source in your report.
4. **Names you were given in the prompt are not verified either.** Check them like any other claim.
5. **Structured output is mandatory.** In the opinions JSON, each match must include `"players": [{"team": "<canonical team>", "name": "<Latin name as in ESPN>", "claim": "out|doubtful|suspended|returns|key", "source": "<site, date>"}]` for every player you mention anywhere in the text. The exporter verifies each name against the roster; an opinion with an unverifiable player is shown on the site with a red warning, so do not let that happen: verify before you write.
6. If you cannot verify, you can still write the opinion without naming players (form, schedule, venue, motivation), and say plainly that squad news was unverifiable.
